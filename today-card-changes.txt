1. ADDED — toISODate() helper function (above getDaysEntries)
   Converts (year, month, day) into a "YYYY-MM-DD" string.
   Month is 0-indexed (matching JS Date), so +1 is applied.
   padStart(2, '0') ensures single-digit months/days get a leading zero.

   function toISODate(year: number, month: number, day: number): string {
     return `${year}-${String(month + 1).padStart(2, '0')}-${String(day).padStart(2, '0')}`;
   }

3. ADDED — hasDaysEntries() function

   Checks whether any entries exist for a given day and returns a boolean.
   Uses a date range query (.gte / .lt) instead of .eq so that full
   timestamp values stored in entry_date still match (e.g. "2026-04-22T14:30:00"
   is caught by gte("2026-04-22") and lt("2026-04-23")).
   Uses new Date(year, month, day + 1) for the upper bound so month-end
   rollover is handled correctly by JavaScript (e.g. April 30 + 1 = May 1).
   Uses count: 'exact', head: true so Supabase returns only the row count
   with no actual row data fetched (efficient existence check).

   async function hasDaysEntries(year, month, day): Promise<boolean> {
     const start = new Date(year, month, day);
     const end   = new Date(year, month, day + 1);
     const fmt   = (d) => d.toISOString().split('T')[0];
     const { count, error } = await supabase
       .from('text_entry')
       .select('*', { count: 'exact', head: true })
       .gte('entry_date', fmt(start))
       .lt('entry_date', fmt(end));
     if (error) throw error;
     return (count ?? 0) > 0;
   }

9. ADDED — localDateString() helper function

   function localDateString(d: Date): string {
     return `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}-${String(d.getDate()).padStart(2, '0')}`;
   }

   WHY: new Date().toISOString() returns the UTC date, not local time.
   If the user's timezone is behind UTC, saving late in the evening would
   write tomorrow's UTC date into entry_date (confirmed: a test entry showed
   2026-04-23 in the DB when local time was still April 22). This helper
   uses getFullYear/getMonth/getDate which are local-timezone-aware.

ROOT CAUSE SUMMARY
────────────────────────────────────────────────────────────

The green card was not appearing because of a chain of three issues:

  1. getDaysEntries queried a non-existent table ('entries') — fixed by
     switching to 'text_entry'.

  2. hasDaysEntries used .eq() on entry_date, but entry_date was stored
     as a full timestamp in some rows — fixed by switching to .gte/.lt
     range query. (Later confirmed the column is actually plain YYYY-MM-DD,
     but the range query works correctly either way.)

  3. note-entry.tsx saved entry_date using toISOString() (UTC), so entries
     saved in the evening were written with tomorrow's date. hasDaysEntries
     looked for today's local date and found nothing — fixed by using
     localDateString() which reads local time parts instead of UTC.

  = '2026-04-23' was saved with the old UTC bug. Edit that row in the
  Supabase dashboard to '2026-04-22' so it is counted correctly.
