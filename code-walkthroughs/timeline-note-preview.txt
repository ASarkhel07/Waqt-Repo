  WALKTHROUGH: Show Note Title & Body Preview on Timeline Cards
  File to edit: app/(tabs)/index.tsx
================================================================================

GOAL
────
Right now, past days with hardcoded entries show a static text string.
We want days that have a REAL saved note (from Supabase's text_entry table)
to display:
  • The note's title (bold, top of card)
  • The first ~2 lines of the body (muted, below the title)
  • A "pen" icon so the user knows it is a text note
  ...similar to how the iPhone Notes app previews entries in a list.

This requires:
  1. Fetching all text entries for the year from Supabase (one query).
  2. Storing them in a Map keyed by ISO date string ("YYYY-MM-DD").
  3. Re-fetching every time the timeline screen comes back into focus
     (so a newly saved note shows up immediately without a full reload).
  4. Passing the map down to DayCard so it can render the preview.
  5. Adding new UI for the note preview card.

STEP 4 — Add fetchYearEntries() function
================================================================================

LOCATION: Near the top of the file (module level, outside the component),
alongside the existing getDaysEntries() and hasDaysEntries() functions.

ADD this function:

  async function fetchYearEntries(userId: string): Promise<Map<string, NotePreview>> {
    const { data, error } = await supabase
      .from('text_entry')
      .select('entry_date, title, body')
      .eq('user_id', userId)
      .gte('entry_date', `${YEAR}-01-01`)
      .lte('entry_date', `${YEAR}-12-31`);

    if (error) {
      console.warn('fetchYearEntries error:', error.message);
      return new Map();
    }

    const map = new Map<string, NotePreview>();
    for (const row of data ?? []) {
      map.set(row.entry_date, { title: row.title, body: row.body });
    }
    return map;
  }

METHOD-BY-METHOD BREAKDOWN:

  supabase.from('text_entry')
    → Opens a query builder targeting the text_entry table.
    → Docs: https://supabase.com/docs/reference/javascript/from

  .select('entry_date, title, body')
    → Only fetch these 3 columns (not *). Keeps the payload small — we do
      not need user_id, id, cover_image_url, etc. for the preview.
    → Docs: https://supabase.com/docs/reference/javascript/select

  .eq('user_id', userId)
    → Filter: only rows belonging to the current user.
    → The RLS policy also enforces this server-side, but doing it client-side
      too is a good explicit habit and reduces row scanning.
    → Docs: https://supabase.com/docs/reference/javascript/eq

  .gte('entry_date', `${YEAR}-01-01`)
  .lte('entry_date', `${YEAR}-12-31`)
    → gte = "greater than or equal", lte = "less than or equal".
      Together they form a date range filter: only 2026 entries.
    → This avoids pulling in old data from previous years if the user
      ever migrates accounts or the app is used across years.
    → Docs: https://supabase.com/docs/reference/javascript/gte

  new Map<string, NotePreview>()
    → A JavaScript Map where the key is "YYYY-MM-DD" (e.g. "2026-04-25")
      and the value is { title, body }.
    → A Map is used instead of a plain object because Map.get() is O(1)
      and avoids prototype chain lookups.
    → MDN Map reference: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map

  for (const row of data ?? [])
    → Iterates each returned row, inserting it into the map.
    → data ?? [] guards against null (if Supabase returns null on empty result).

STEP 6 — Add useFocusEffect to fetch (and re-fetch) entries
================================================================================

LOCATION: Inside TimelineScreen, after the existing useEffect blocks.

FIRST, add this import at the top of the file:
  import { useFocusEffect } from 'expo-router';

THEN add this hook inside the component:

  useFocusEffect(
    useCallback(() => {
      supabase.auth.getUser().then(({ data: { user } }) => {
        if (!user) return;
        fetchYearEntries(user.id).then(setEntryMap).catch(console.error);
      });
    }, [])
  );

METHOD-BY-METHOD BREAKDOWN:

  useFocusEffect(callback)
    → Runs the callback every time this screen comes into focus.
    → This is different from useEffect (which only runs on mount).
    → WHY THIS MATTERS: when the user saves a note in note-entry.tsx and
      taps Back, the timeline screen comes back into focus. useFocusEffect
      fires again and re-fetches the entries — so the new note appears
      immediately on the card without needing a full app reload.
    → Expo Router docs: https://docs.expo.dev/router/reference/hooks/
    → React Navigation docs (same hook): https://reactnavigation.org/docs/use-focus-effect/

  useCallback(() => {...}, [])
    → useFocusEffect requires the callback to be wrapped in useCallback.
      This is a requirement of the hook's API — without it you get an
      infinite loop because the function reference changes on every render.
    → React docs on useCallback: https://react.dev/reference/react/useCallback

  supabase.auth.getUser()
    → Gets the currently signed-in user without making a network request
      (reads from the cached session in AsyncStorage).
    → Returns { data: { user } } where user is null if not signed in.
    → Docs: https://supabase.com/docs/reference/javascript/auth-getuser

  fetchYearEntries(user.id).then(setEntryMap)
    → Calls the function from Step 4 and, when it resolves, calls
      setEntryMap with the result — triggering a re-render of the timeline.

LOCATION: Inside DayCard, just before the final return (the existing text card).

The existing text card for hardcoded entries currently looks like:

    <TouchableOpacity style={styles.textCard} ...>

ADD a new block ABOVE that existing return, to handle real Supabase entries:

  if (notePreview) {
    return (
      <TouchableOpacity style={styles.noteCard} activeOpacity={0.85} onPress={onPress}>
        <Ionicons
          name="create-outline"
          size={16}
          color="rgba(255,255,255,0.4)"
          style={styles.noteCardIcon}
        />
        {notePreview.title ? (
          <Text style={styles.noteCardTitle} numberOfLines={1}>
            {notePreview.title}
          </Text>
        ) : (
          <Text style={styles.noteCardNoTitle}>Untitled</Text>
        )}
        {notePreview.body ? (
          <Text style={styles.noteCardBody} numberOfLines={2}>
            {notePreview.body}
          </Text>
        ) : null}
      </TouchableOpacity>
    );
  }

METHOD-BY-METHOD BREAKDOWN:

  if (notePreview)
    → This guard means: only render the rich preview if the day has a real
      Supabase entry. Days without entries still fall through to the existing
      empty/hardcoded card rendering below.

  numberOfLines={1} on the title
    → React Native prop that truncates text after 1 line and adds "..." at
      the end. Prevents a long title from overflowing the card height.
    → Docs: https://reactnative.dev/docs/text#numberoflines

  numberOfLines={2} on the body
    → Same, but allows 2 lines — enough to give the user a feel for what
      they wrote, without overwhelming the card.

  "Untitled" fallback
    → title is nullable (user can save a note with no title). Show a muted
      "Untitled" placeholder so the card never looks blank.

STEP 10 — Update extraData on FlatList so it re-renders when entryMap changes
================================================================================

LOCATION: The <FlatList> JSX, around line 389.

CURRENT:
  extraData={[activeCard, todayHasEntry]}

CHANGE TO:
  extraData={[activeCard, todayHasEntry, entryMap]}

WHY:
  FlatList by default only re-renders items when its `data` prop changes.
  extraData tells FlatList "also re-render if any of these values change."
  Without this, cards would not update when entryMap is populated after
  the initial fetch — the list would look empty even after data arrives.
  React Native FlatList docs: https://reactnative.dev/docs/flatlist#extradata
